La API de Bing Webmaster devuelve listas vacías mientras el panel muestra datos

Por Nesim Razon, desarrollador móvil independiente · 2026-11-20

#Notas de desarrollo

Unas semanas después de lanzar un sitio, el panel de Bing Webmaster Tools mostraba palabras clave de búsqueda, páginas y enlaces entrantes, pero la API devolvía listas vacías para lo mismo. Solo una parte de la API tenía datos. Si tu propio panel construido sobre esa API parece vacío, esto es lo que encontré, qué llamadas funcionaron y cómo llené el hueco con honestidad.

La discrepancia

En el panel de Bing, la página Search Performance listaba seis palabras clave, tres páginas y un desglose por país y dispositivo. La página Backlinks mostraba dos dominios que enlazan y veinte páginas que enlazan. Mi informe, que llama a la API, mostraba un puñado de totales y un gráfico y nada más, y sospeché de mi propio código.

Probé cada llamada a mano

Llamé a los métodos de la API uno por uno. La llamada de tráfico diario devolvió dos días de clics e impresiones. La de estadísticas de rastreo devolvió páginas rastreadas, páginas indexadas y recuentos de enlaces entrantes. La de feeds devolvió mi sitemap y cuántas URL había leído Bing de él. La de cuota de envíos devolvió los límites diario y mensual.

Las llamadas de consultas, páginas, consulta por página, recuentos de enlaces, enlaces de una URL y estadísticas de palabras clave devolvieron todas listas vacías con un estado de éxito normal. No había ningún error que capturar. Los datos simplemente no se exponían aún por la API, aunque el panel los tuviera.

Un subproducto útil

La llamada de feeds mostró que Bing había leído 328 URL de mi sitemap cuando el archivo tenía 381. Eso me dijo que el sitemap estaba desactualizado por su parte, y reenviarlo en el panel lo arregló. Detalles pequeños como este se pasan por alto fácilmente si solo miras los totales.

Cómo traté el hueco

No quería una pestaña vacía ni inventar números. Leí las tablas del panel una vez desde el navegador, las guardé en un archivo pequeño con la fecha y el rango de fechas, e hice que el informe use ese archivo cuando las listas de la API estén vacías. El informe muestra una nota clara de que esas listas proceden del panel en una fecha dada, y pasa a la API automáticamente cuando esta devuelve datos.

Lecciones

  • Una lista vacía con estado de éxito no prueba que no haya datos. Compara con el panel antes de culpar a tu código.
  • Prueba cada método de la API por separado y guarda las respuestas en bruto de la primera ejecución.
  • Etiqueta la fuente y la fecha de cada número que copies de un panel.
  • Usa las llamadas extra: los recuentos de lectura del sitemap y las estadísticas de rastreo encontraron un problema real.
  • Vuelve a comprobar en una o dos semanas, porque los sitios nuevos se llenan despacio.

Preguntas frecuentes

¿Por qué la API de Bing devuelve listas vacías de consultas y páginas?

En un sitio nuevo los datos de detalle pueden no estar expuestos aún por la API, aunque el panel ya los muestre. Las llamadas tienen éxito pero no devuelven filas.

¿Qué llamadas de la API de Bing funcionaron en un sitio nuevo?

Los totales de tráfico diario, las estadísticas de rastreo, el estado del feed del sitemap y la cuota de envío de URL.

¿Es un error de mi código?

Prueba primero cada llamada a mano. Si la respuesta en bruto es una lista vacía con estado de éxito, los datos no vienen de la API.

¿Cómo puedo mostrar los datos mientras tanto?

Copia las tablas del panel a un archivo con fecha y etiquétalas con claridad, y vuelve a la API cuando devuelva filas.
