Leer Crashlytics desde un asistente de código con IA: la trampa de la carpeta del proyecto

Por Nesim Razon, desarrollador móvil independiente · 2026-11-20

#Notas de desarrollo#Android

Si tu asistente de código con IA está conectado al servidor MCP de Firebase pero no ve ninguna herramienta de Crashlytics, la causa probablemente es la carpeta del proyecto y no un inicio de sesión roto. El servidor activa las herramientas según los SDK de Firebase que encuentra en la carpeta a la que apunta. Si lo apuntas a una app Android que usa Crashlytics, las herramientas aparecen. Aquí cuento cómo lo descubrí y qué compruebo antes de fiarme de un informe.

El síntoma

Le pedí al asistente que revisara los informes de fallos de varias apps. Podía listar apps y leer detalles del proyecto, pero no había ninguna herramienta de Crashlytics. Reconectar el servidor e iniciar sesión de nuevo no cambió nada, y el inicio de sesión estaba bien, porque otras herramientas de Firebase funcionaban.

La causa: las herramientas siguen a la carpeta del proyecto

El servidor MCP de Firebase activa algunas herramientas de forma automática según los SDK de Firebase que detecta en el directorio del proyecto que usa. Mi directorio por defecto tenía una pequeña configuración de Firebase de un proyecto de panel que no incluye el SDK de Crashlytics, así que el servidor nunca ofreció las herramientas de Crashlytics.

La solución sin editar archivos de configuración

El entorno se puede cambiar desde dentro de la sesión. Llamé a la herramienta de actualización del entorno con el directorio del proyecto apuntando a la carpeta de una app Android que sí usa Crashlytics, junto con el proyecto de Firebase de esa app. Después, buscar “crashlytics” en la lista de herramientas devolvió las de informes e incidencias. No toqué ningún archivo de ajustes.

Lee la guía antes del primer informe

El servidor también publica una guía como recurso, con la forma correcta de pedir informes. Leerla primero me ahorró adivinar filtros. Es una lectura corta y explica qué tipos de informe existen y qué necesita cada uno.

Comprueba el proyecto activo cada vez

Las herramientas actúan sobre el proyecto de Firebase activo. Una vez creé una app en el proyecto equivocado porque el activo era distinto del que yo suponía. Ahora, antes de cualquier acción de escritura, pido al servidor el entorno actual y comparo el identificador del proyecto con el que quiero.

No leas un error como “sin fallos”

Una app devolvió un 404 cuando pedí sus principales problemas. Eso no significaba cero fallos. En esa app la recogida de datos de fallos está desactivada a propósito, así que no hay nada que leer. Un informe solo tiene sentido si la recogida está activa para la app y la compilación que te importa, por eso anoto qué apps están cubiertas antes de decir que una versión está limpia.

Lista de comprobación

  • ¿No hay herramientas de Crashlytics? Apunta el servidor a una carpeta de app que contenga el SDK de Crashlytics.
  • Fija el directorio del proyecto y el proyecto activo en una sola actualización del entorno y confirma ambos.
  • Lee el recurso de la guía de informes antes de pedir datos.
  • Confirma el proyecto activo antes de crear o cambiar algo.
  • Sabe qué apps tienen la recogida activada, para no confundir un resultado vacío con uno limpio.

Preguntas frecuentes

¿Por qué el servidor MCP de Firebase no muestra herramientas de Crashlytics?

El servidor activa las herramientas según los SDK de Firebase que encuentra en su directorio de proyecto. Si esa carpeta no tiene el SDK de Crashlytics, las herramientas de Crashlytics quedan ocultas.

¿Cómo hago que aparezcan las herramientas de Crashlytics?

Actualiza el entorno del servidor para que el directorio del proyecto sea una carpeta de app que use Crashlytics y fija el proyecto de Firebase correspondiente. Luego busca de nuevo en la lista de herramientas.

¿Un 404 en los principales problemas significa que la app no tiene fallos?

No. Puede significar que la recogida de fallos está desactivada en esa app, de modo que no hay datos que devolver.

¿Tengo que editar un archivo de configuración?

No necesariamente. La herramienta de actualización del entorno puede cambiar el directorio y el proyecto activo durante la sesión.
