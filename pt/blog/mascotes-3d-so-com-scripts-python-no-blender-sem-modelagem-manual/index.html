Mascotes 3D só com scripts do Blender, sem modelar à mão

Por Nesim Razon, desenvolvedor mobile independente · 2026-11-28

#Notas de desenvolvimento#Design de jogos

Sou desenvolvedor, não artista 3D. Nunca esculpi um personagem com o mouse. Mesmo assim, os companheiros do jogo de caminhada que estou preparando são criaturinhas parecidas com brinquedos de argila renderizadas em 3D. Elas são montadas inteiramente por scripts Python que o Blender executa pela linha de comando, e digo com clareza: escrevi esses scripts com a ajuda de um assistente de inteligência artificial. Veja como o processo funciona e o que aprendi.

A ideia: descrever o personagem em código

O Blender consegue executar um arquivo Python sem abrir a janela. Dentro desse arquivo, o módulo bpy faz o que eu faria à mão: criar formas, dar materiais, posicionar luzes e câmera e gerar uma imagem.

Assim um personagem vira uma função. Uma chamada faz o corpo, a seguinte a barriga, depois os olhos, as orelhas e os pés, cada um com posição, tamanho e cor. Nada fica guardado em um arquivo de projeto que só eu conseguiria abrir e entender. Se uma criatura precisa de olhos maiores, muda um número e o script gera todos os quadros de novo.

Para quem não sabe modelar, isso importa. Posso olhar uma imagem, dizer em palavras o que está errado e ver a mudança como poucas linhas editadas que consigo revisar.

Poucas formas simples rendem muito

Os cinco companheiros do meu script usam um conjunto bem pequeno de peças. Uma esfera que pode ser esticada. Um cone com bordas suavizadas para orelhas e bicos. Um aro para um cachecol ou óculos. Uma curva com espessura para a boca, um olho fechado ou um caule.

Formas complicadas são evitadas de propósito. Uma criatura fofa é uma bola cercada por vinte e seis bolas menores, espalhadas pelo ângulo áureo para não se alinharem e pulando o lado onde fica o rosto. Uma criatura de pedra é uma esfera cuja superfície é levemente empurrada por uma textura de ruído de nuvem.

O rosto é uma função compartilhada. Dois olhos escuros, cada um com dois pequenos brilhos brancos, e bochechas suaves. Esses brilhos dão ao personagem mais do que qualquer quantidade de geometria extra.

Materiais, luzes e a armadilha da cor

Todos os materiais partem do sombreador padrão baseado em física com poucos valores alterados: rugosidade, uma fina camada de verniz e um pouco de espalhamento de luz sob a superfície, que dá a aparência de brinquedo macio. As cores são escritas nos códigos usuais de seis dígitos e convertidas para valores lineares no código, porque o Blender espera números lineares.

A iluminação é igual para todas as criaturas: uma luz principal quente, um preenchimento mais frio, uma luz quente por trás e um céu azul-claro. A câmera é ortográfica, então o personagem não muda de forma ao se mover.

Um ajuste passa fácil despercebido. Versões recentes do Blender aplicam por padrão uma transformação de cor com jeito de cinema, e minhas cores vivas saíam lavadas. Mudar a transformação de visualização para Standard trouxe de volta as cores que eu tinha escrito.

Animação é aritmética

Não há ossos nem quadros-chave. Cada animação é uma função que recebe o número do quadro e devolve poucos valores: quanto o corpo balança para cima e para baixo, quanto oscila, se os olhos estão fechados e a que altura pula. Ondas senoidais fazem quase todo o trabalho.

São quatro animações de vinte e quatro quadros cada. A caminhada move os pés em fases opostas e faz o corpo balançar duas vezes por ciclo. O descanso é uma respiração lenta com uma piscada curta perto do fim. A alegria são dois pulinhos com um achatamento antes de cada um e olhos curvos felizes. O sono mantém os olhos fechados e respira devagar.

A cada quadro o script reinicia o Blender com uma cena vazia e monta o personagem outra vez. É um desperdício, mas elimina toda uma classe de erros em que uma sobra do quadro anterior altera o seguinte.

Dos quadros a algo que o app possa usar

A renderização tem fundo transparente. Um segundo script Python comum pega os quadros e acrescenta a sombra no chão: uma elipse desfocada desenhada com uma biblioteca de imagens, um pouco menor quando o personagem está no alto. Desenhar a sombra depois é mais simples do que pedir ao renderizador que a capture, e é fácil de ajustar.

A mesma etapa pode gravar uma prévia animada, que é o que olho enquanto ajusto. Para o aplicativo, outro script organiza os quadros em uma folha com seis de largura, assim o jogo carrega uma imagem por animação e desenha a parte necessária.

Uma opção na linha de comando gira o personagem para renderizá-lo de costas, sem código extra para uma segunda vista.

Trabalhando com uma IA em formas

O ciclo é curto: descrevo o que quero, o assistente edita o script, o Blender renderiza e eu olho. Meu julgamento entra só na última etapa, e é um julgamento de verdade. Uma criatura tecnicamente correta ainda pode parecer triste, pesada ou estranha.

As descrições funcionam melhor quando falam da imagem e não do código. Dizer mais redonda, orelhas mais juntas ou os olhos parecem surpresos levou a mudanças úteis. Também aprendi a renderizar primeiro uma única imagem parada e gerar todos os quadros só depois que a forma foi aprovada.

A mesma abordagem deu ao meu jogo de estilingue os onze retratos de mensageiros, com outro script e a mesma ideia.

Limites

Esse método serve para personagens macios e arredondados feitos de peças simples. Seria uma má escolha para pessoas realistas, tecido ou qualquer coisa que precise de esqueleto. Dá para perceber que o visual é montado com primitivas, e escolhi um estilo em que isso é uma virtude.

Renderizar leva tempo, e o script que gera toda a arte do jogo demora o bastante para eu ter aprendido a não interrompê-lo, porque ele esvazia a pasta de saída antes de começar.

Por que cinco personagens parecem uma família

A coerência vem quase de graça quando tudo é código. Todas as criaturas usam a mesma função de materiais, que cria cada material uma vez e o reaproveita pelo nome. Compartilham a função do rosto e a dos pés, posam diante da mesma câmera e são iluminadas pelas mesmas três lâmpadas. Um companheiro novo herda tudo isso e só precisa ser diferente onde eu quiser.

As diferenças ficam fáceis de ler no arquivo: a raposa ganha cones para as orelhas, um rabo feito de uma curva grossa e um nariz escuro; a coruja, aros que parecem óculos. Comparar dois personagens é comparar duas funções curtas.

Opções que uso enquanto ajusto

O script aceita algumas opções depois dos argumentos usuais do Blender: quais personagens renderizar, quantos quadros, o tamanho da imagem, qual animação, o ângulo de visão e uma chave para uma única imagem parada. Uma imagem pequena é o jeito rápido de avaliar uma forma. As animações completas no tamanho final são o jeito lento de produzir o que será publicado.

O motor é o de traçado de raios, com poucas amostras e remoção de ruído. O script tenta usar a placa de vídeo e recorre ao processador se não conseguir, então o mesmo comando funciona em um computador sem placa adequada, só que mais devagar.

Se quiser experimentar

  • Comece com uma criatura e uma imagem parada.
  • Deixe cada tamanho e cor no código, onde você os veja.
  • Compartilhe uma única função de rosto entre os personagens.
  • Ajuste a transformação de visualização para Standard se as cores parecerem pálidas.
  • Use câmera ortográfica e fundo transparente para os sprites.
  • Acrescente a sombra depois, em uma etapa separada.

Perguntas frequentes

É preciso saber modelar em 3D para fazer esse tipo de personagem?

Não para formas arredondadas simples. É preciso avaliar imagens e descrever o que mudar.

Quem escreveu os scripts?

Escrevi com um assistente de inteligência artificial e confiro o resultado olhando as renderizações.

Como o personagem é animado sem ossos?

Cada quadro é montado a partir de poucos números, quase todos ondas senoidais, que movem e achatam as peças.

Por que minhas cores no Blender parecem lavadas?

A transformação de cor padrão as altera. Usar Standard na transformação de visualização mantém as cores digitadas.
