A API do Bing Webmaster devolve listas vazias enquanto o painel mostra dados

Por Nesim Razon, desenvolvedor mobile independente · 2026-11-20

#Notas de desenvolvimento

Algumas semanas depois de lançar um site, o painel do Bing Webmaster Tools mostrava palavras-chave de busca, páginas e links de entrada, mas a API devolvia listas vazias para as mesmas coisas. Só uma parte da API tinha dados. Se o seu próprio painel construído sobre essa API parece vazio, isto é o que encontrei, quais chamadas funcionaram e como preenchi a lacuna com honestidade.

A discrepância

No painel do Bing, a página Search Performance listava seis palavras-chave, três páginas e uma divisão por país e dispositivo. A página Backlinks mostrava dois domínios que linkam e vinte páginas que linkam. Meu relatório, que chama a API, mostrava um punhado de totais e um gráfico e nada mais, e suspeitei do meu próprio código.

Testei cada chamada à mão

Chamei os métodos da API um por um. A chamada de tráfego diário devolveu dois dias de cliques e impressões. A de estatísticas de rastreamento devolveu páginas rastreadas, páginas indexadas e contagens de links de entrada. A de feeds devolveu meu sitemap e quantas URLs o Bing leu dele. A de cota de envios devolveu os limites diário e mensal.

As chamadas de consultas, páginas, consulta por página, contagens de links, links de uma URL e estatísticas de palavras-chave devolveram todas listas vazias com status de sucesso normal. Não havia erro para capturar. Os dados simplesmente ainda não eram expostos pela API, mesmo que o painel os tivesse.

Um subproduto útil

A chamada de feeds mostrou que o Bing tinha lido 328 URLs do meu sitemap quando o arquivo tinha 381. Isso me disse que o sitemap estava desatualizado do lado deles, e reenviá-lo no painel resolveu. Detalhes pequenos assim passam fácil se você só olha os totais.

Como tratei a lacuna

Eu não queria uma aba vazia nem inventar números. Li as tabelas do painel uma vez pelo navegador, salvei em um arquivo pequeno com a data e o intervalo de datas, e fiz o relatório usar esse arquivo quando as listas da API estiverem vazias. O relatório mostra uma nota clara de que essas listas vêm do painel em uma data, e passa para a API automaticamente quando ela devolve dados.

Lições

  • Uma lista vazia com status de sucesso não prova que não há dados. Compare com o painel antes de culpar seu código.
  • Teste cada método da API separadamente e guarde as respostas brutas da primeira execução.
  • Rotule a fonte e a data de cada número que copiar de um painel.
  • Use as chamadas extras: as contagens de leitura do sitemap e as estatísticas de rastreamento acharam um problema real.
  • Verifique de novo em uma ou duas semanas, porque sites novos enchem devagar.

Perguntas frequentes

Por que a API do Bing devolve listas vazias de consultas e páginas?

Em um site novo os dados de detalhe podem ainda não ser expostos pela API, mesmo que o painel já os mostre. As chamadas têm sucesso mas não devolvem linhas.

Quais chamadas da API do Bing funcionaram em um site novo?

Os totais de tráfego diário, as estatísticas de rastreamento, o estado do feed do sitemap e a cota de envio de URLs.

É um erro no meu código?

Teste primeiro cada chamada à mão. Se a resposta bruta é uma lista vazia com status de sucesso, os dados não vêm da API.

Como posso mostrar os dados enquanto isso?

Copie as tabelas do painel para um arquivo com data e rotule com clareza, e volte para a API quando ela devolver linhas.
