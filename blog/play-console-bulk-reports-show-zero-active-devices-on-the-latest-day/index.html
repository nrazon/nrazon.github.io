Play Console Bulk Reports Show 0 Active Devices on the Latest Day

By Nesim Razon, independent mobile developer · 2026-11-20

#Dev notes#Android

If you read the Google Play bulk install reports yourself and a dashboard suddenly says an app has 0 active devices, check the date. The newest day in the file often has a zero in the Active Device Installs column because Google has not calculated it yet. Installs and uninstalls for that day are filled in, which makes the zero look like real data. Here is what I saw and the rule I now use.

What I saw

My weekly report reads the installs overview file for every app. Several apps suddenly showed zero active devices. In the file the previous day looked normal and the last row was the odd one. For example one utility app went from 370 on the day before to 0 on the last row, a lottery app from 2,710 to 0, and a small game from 10 to 0. On that same last row the daily installs and uninstalls were not empty.

Because my report simply took the last row, it printed zero. New apps with only a handful of users looked the most suspicious, since a few installs and a zero in the same row seemed contradictory.

Why the zero is not real

Active devices is a rolling figure, so Google needs time to compute it, while installs and uninstalls are event counts that arrive immediately. The newest day therefore has event counts but no active-device value yet. It is a delay, not a drop in users. Older rows in the same file keep their numbers.

The rule that fixed my report

I now look at the last seven days and use the most recent value above zero as the active-device figure. The report says which date that figure comes from and notes when the newest day was skipped. The monthly chart and the country list use the same date, so they do not collapse to zero on the last point.

Other columns that mislead

  • Total User Installs is always zero in the files I read, so I do not show it. A “total installs: 0” line next to real installs looks like a bug in your own report.
  • Installs minus uninstalls does not equal active devices. Active devices counts devices that were active in a recent window, so a new install that was never opened may not appear.
  • With very small numbers the values bounce around, for example 0, 2, 0, 3 on consecutive days. Do not read a trend into them.

How to guard your own dashboard

Treat the newest one or two days of any bulk report as provisional. Do not use the last row for a headline number, compare week over week using complete days, and add a short note under any figure that skips a day. A tiny sentence about the source date prevents a lot of false alarms.

Frequently asked questions

Why does the latest day show 0 active devices?

Google has not computed the active-device figure for the newest day yet, while installs and uninstalls for that day are already filled in.

Is the user count really dropping to zero?

No. Earlier rows in the same file keep their values. The zero is a processing delay.

Which value should I use as the current active devices?

The most recent value above zero from the last few days, with the date shown next to it.

Should installs minus uninstalls match active devices?

No. They measure different things, and a device that never opened the app may not count as active.
