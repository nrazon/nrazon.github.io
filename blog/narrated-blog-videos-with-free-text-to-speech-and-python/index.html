Narrated Blog Videos With Free Text-to-Speech and Python

By Nesim Razon, independent mobile developer · 2026-11-20

#Dev notes

I turn every blog article into a narrated YouTube video with one script: a free text-to-speech voice reads the article, Python draws a diagram for each section, and ffmpeg puts it together. No camera, no microphone, no editing program. This post explains the pipeline, the pronunciation trap that took the most time and the choices that keep the videos honest.

The pipeline in one paragraph

The script loads the article from the same file that builds the blog page. For each sentence it creates a speech file with the free Microsoft neural voice service available through a Python package, then draws a frame with the section diagram and the current subtitle using Pillow, and finally ffmpeg joins frames and audio into a 1920 by 1080 video at 30 frames per second. A second function makes the thumbnail at 1280 by 720.

One voice, one language

I tried Turkish, Spanish and Portuguese voices too and rejected them. A single Turkish voice reads English technical words in Turkish, a mixed voice sounds wrong, and switching between two voices created pauses and a tone change at every switch. The channel now has one English voice with a slightly slower rate, and the site stays multilingual in text only.

The pronunciation trap

Developer articles are full of words a voice cannot read: product names, camel case identifiers, abbreviations. The solution is a small dictionary applied only to the text that goes to the voice, while the subtitles keep the original spelling. An identifier like a bundle version key becomes separate words, and the iOS word becomes letters. I cannot hear the result myself, so every new word that sounds wrong gets reported by listening and added to the dictionary, which grows over time.

Diagrams that match the article

A title card plus bullet text is not enough for a long video. Each article gets its own list of scenes built from a few drawing primitives: flows, comparison panels, code lines, number cards and checklists. The scene appears step by step as each sentence is read, so the picture follows the narration.

Publishing without babysitting

The upload script sends each video as private with a scheduled publish time, adds the thumbnail, sets a playlist and writes a description that links the article. Every description states that the narration is AI-generated, which I think is the honest thing to do.

What I would tell a beginner

  • Start with one article and one voice. Get a clean result before you build a scene library.
  • Keep spoken text and subtitle text separate from day one.
  • Listen to every video once before it goes public. Mispronunciations are the most common defect.
  • Do not publish too many near-identical videos in a short time. Vary the visuals so each video earns its place.
  • Say in the description that the voice is synthetic.

Frequently asked questions

Do I need a microphone or camera?

No. A free neural text-to-speech voice reads the article and Python draws the images.

How do I fix mispronounced technical words?

Add them to a replacement dictionary that changes only the text sent to the voice, so the subtitles stay correct.

Can the same script produce other languages?

It can, but in my tests the quality of mixed technical English was worse, so I keep the videos English.

Should I tell viewers the voice is synthetic?

Yes. A short note in every description is simple and honest.
